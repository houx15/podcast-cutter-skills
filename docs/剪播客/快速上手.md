# 快速上手：从录音到 cut.wav

本文以一期双轨访谈录音为例，完整走完阶段 1–4。假设你已经安装好依赖并配置好 `.env`。

---

## 前提

```bash
# 检查依赖是否就绪
ffmpeg -version          # 需要 5.x 或更高
python --version         # 需要 3.10+
pip install -e ".[dev]"  # 安装 Python 包

# 检查环境变量
grep -E 'VOLC_API_KEY|LLM_API_KEY' .env
```

`.env` 中至少需要填写：

```dotenv
VOLC_API_KEY=your_volcano_key
LLM_API_KEY=your_ark_key
LLM_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
LLM_MODEL=doubao-seed-2-0-code-preview-260215
```

如果没有 TOS/S3 存储桶，上传会自动回退到 uguu.se（文件公开、24小时后删除），适合测试。

---

## 准备录音文件

将两轨录音放入 `recordings/` 目录（支持 `.wav`、`.m4a`、`.mp3`）：

```
recordings/
├── host.m4a     # 主持人轨
└── guest.m4a    # 嘉宾轨
```

---

## 阶段 1：转录

### 1.0 准备音频

```bash
python shared/scripts/prepare_audio.py \
  --track1 recordings/host.m4a \
  --track2 recordings/guest.m4a \
  --ep-dir output/2026-05-08-ep01
```

生成：
- `output/2026-05-08-ep01/input/working_track1.wav` — 主持人轨，单声道 16-bit PCM
- `output/2026-05-08-ep01/input/working_track2.wav` — 嘉宾轨
- `output/2026-05-08-ep01/input/audio_meta.json` — 采样率、时长等元数据

### 1.2 提交 ASR 任务

```bash
python shared/scripts/volcano_submit.py --ep-dir output/2026-05-08-ep01
```

脚本会先上传 working WAV（TOS → S3 → uguu.se），然后向 Volcano Engine 提交异步 ASR 任务，将 task_id 写入：
- `output/2026-05-08-ep01/1_transcribe/task_id_track1.txt`
- `output/2026-05-08-ep01/1_transcribe/task_id_track2.txt`

### 1.2 轮询 ASR 结果

```bash
python shared/scripts/volcano_query.py --ep-dir output/2026-05-08-ep01
```

脚本每 10 秒轮询一次，直到两轨都完成。完成后写入：
- `output/2026-05-08-ep01/1_transcribe/volcano_raw_track1.json`
- `output/2026-05-08-ep01/1_transcribe/volcano_raw_track2.json`

典型耗时：音频时长的 20–40%（一期 60 分钟的录音约需 15–25 分钟）。

**常见错误：**
- `45000001` — API key 或格式错误，检查 `.env`
- `45000132` — 音频超过 512 MB，先用 ffmpeg 转码：
  ```bash
  ffmpeg -i recordings/host.m4a -ar 16000 -ac 1 -b:a 48k recordings/host_compressed.mp3
  ```

### 1.3 合并转录结果

```bash
python shared/scripts/transcribe_merge.py --ep-dir output/2026-05-08-ep01
```

将两轨词流按 `start_ms` 排序合并，S1 对应 track1（主持人），S2 对应 track2（嘉宾）。输出：
- `output/2026-05-08-ep01/1_transcribe/words.json`

### 1.4 切分句子

```bash
python shared/scripts/make_sentences.py --ep-dir output/2026-05-08-ep01
```

按说话人切换、停顿（≥ 500ms）或长度（≥ 50 字符）将词序列分割为句子。输出：
- `output/2026-05-08-ep01/1_transcribe/sentences.json`

---

## 阶段 2：LLM 分析

三轮分析，逐步识别应删除的片段。每轮约需 30–90 秒。

### 2.1 粗剪分析

```bash
python shared/scripts/analyze_rough.py --ep-dir output/2026-05-08-ep01
```

LLM 依据 `shared/rules/editing/*.md` 中的规则，识别录前闲聊、完全题外话、长停顿等大段内容。输出：
- `output/2026-05-08-ep01/2_analysis/rough_cuts.json`

### 2.2 精剪分析

```bash
python shared/scripts/analyze_fine.py --ep-dir output/2026-05-08-ep01
```

在粗剪基础上，词级别识别填充词（"嗯"、"啊"）和冗余重复。输出：
- `output/2026-05-08-ep01/2_analysis/fine_cuts.json`

### 2.3 自审

```bash
python shared/scripts/self_review.py --ep-dir output/2026-05-08-ep01
```

LLM 对前两轮建议进行质检，标出可能误删的片段，补充漏掉的删除建议。输出：
- `output/2026-05-08-ep01/2_analysis/self_review.json`

---

## 阶段 3：人工审查

### 3.0 生成审查页面

```bash
python shared/scripts/generate_review_html.py --ep-dir output/2026-05-08-ep01
```

生成：
- `output/2026-05-08-ep01/3_review/review_enhanced.html`
- `output/2026-05-08-ep01/3_review/review_state.json`（初始状态）

### 启动本地服务

```bash
python shared/scripts/review_server.py --ep-dir output/2026-05-08-ep01 --port 5050
```

服务运行后，在浏览器中打开：
```
output/2026-05-08-ep01/3_review/review_enhanced.html
```

页面展示所有 AI 删除建议，每条可以：
- **保留**（接受 AI 建议）
- **编辑**（调整时间区间后保留）
- **拒绝**（取消这条删除，保留该音频段）
- **新增**（手动标记需要删除的区间）

所有操作实时通过 `PATCH /state` 保存到 `review_state.json`。

### 3.1 导出决策

审查完成后，点击页面中的"导出"按钮，或运行：

```bash
curl -X POST http://localhost:5050/export \
  -H 'Content-Type: application/json' \
  -d '{"user_notes": "前3分钟全删", "feedback_for_learning": []}'
```

生成：
- `output/2026-05-08-ep01/3_review/delete_segments_edited.json`

## 阶段 4：剪辑

### 4.0 剪切音频

```bash
python shared/scripts/cut_audio.py --ep-dir output/2026-05-08-ep01
```

- 将 `delete_segments_edited.json` 中所有非 `rejected_by_user` 的区间从 working WAV 中切除
- 每个拼接点使用 25ms 三角形交叉淡化
- 完成后自动检查输出峰值（> -10 dB），防止输出静音文件

默认处理 track1；双轨合并模式由脚本自动检测 `audio_meta.json`。

生成：
- `output/2026-05-08-ep01/4_cut/cut.wav`

### 4.1 裁剪首尾静音

```bash
python shared/scripts/trim_silences.py --ep-dir output/2026-05-08-ep01
```

检测 cut.wav 首尾的静音区域，保留最多 200ms 过渡，原地覆盖。若没有显著静音则跳过（幂等）。

最终结果：
```
output/2026-05-08-ep01/4_cut/cut.wav
```

## 重跑某个阶段

所有脚本都是幂等的。如果想在修改规则后重跑分析，直接重新执行对应阶段即可，它会覆盖上一次的输出：

```bash
# 修改 shared/rules/editing/ 后重跑分析
python shared/scripts/analyze_rough.py --ep-dir output/2026-05-08-ep01
python shared/scripts/analyze_fine.py  --ep-dir output/2026-05-08-ep01
python shared/scripts/self_review.py   --ep-dir output/2026-05-08-ep01
```

审查阶段需要重新生成 HTML 并重启服务器：

```bash
python shared/scripts/generate_review_html.py --ep-dir output/2026-05-08-ep01
python shared/scripts/review_server.py        --ep-dir output/2026-05-08-ep01 --port 5050
```

## 自定义剪辑规则

- **编辑规则**：修改 `shared/rules/editing/*.md`，下次运行分析脚本时生效
- **用户偏好**：修改 `shared/rules/users/default/preferences.yaml`，调整积极程度（`aggressiveness`）、置信度阈值（`min_confidence`）等
- **热词**：在 `shared/rules/users/default/hotwords.txt` 中添加专有名词，提高 ASR 识别准确率（需在提交 ASR 任务前修改）
